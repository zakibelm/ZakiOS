# Second audit externe (commit 93449b9)

Note donnée : 7,5/10 pour le moteur de catalogue ; bon candidat pour un pilote avec revue humaine, pas encore pour une activation autonome. L'audit a confirmé les 35 tests, la CI réussie, `yaml.safe_load` et la vérification des commits. Il n'a pas reconstruit le catalogue depuis les sources. Chaque défaut ci-dessous a été reproduit par un test avant correction.

## Défauts corrigés (moteur 0.3.0)

| Défaut | Correction | Test |
|---|---|---|
| Une validation restait appliquée après modification du composant | validation liée à `fingerprint_sha256` ; sinon « périmée » et visible dans le rapport | `test_validation_is_invalidated_when_content_changes` |
| Un CSV modifié passait si le nombre de lignes restait égal | `verify` régénère le CSV depuis le registre et compare | `test_csv_edit_with_same_row_count_is_detected` |
| Une panne au second renommage laissait `catalog/` absent | échange atomique (`renameat2`) ; repli avec restauration immédiate | `test_swap_never_leaves_the_catalog_missing` |
| Dossiers temporaires à nom fixe | verrou + dossier temporaire unique | `test_concurrent_generation_is_refused` |
| Métadonnées invalides évaluées quand même | statut « métadonnées invalides — revue requise », sans comparaison | `test_invalid_metadata_is_quarantined` |
| Empreinte d'un mod ou d'un hook limitée au fichier représentatif | empreinte sur tous les fichiers de comportement | `test_composed_components_fingerprint_covers_all_behavior_files` |
| `verify` trop léger | schéma, types, hexadécimaux, références, décisions autorisées, comptes par source et par type | tests de falsification |
| `--allow-dirty` pouvait passer pour exact | `build_mode: experimental_dirty` et avertissement | `test_dirty_build_is_experimental` |
| Familles comparées séparément | statut « chevauchement inter-couches » (53 composants aitmpl concernés) | `test_cross_layer_overlap_is_flagged` |

## Précisions retenues

- Retrouver les composants ZAKI OS complète la comparaison, mais ne valide aucune décision : la revue fonctionnelle reste nécessaire.
- La licence du code de ZakiOS et celles des composants tiers sont deux sujets distincts.
- Le plugin n'est représenté que par son manifeste : ses agents et skills internes sont des composants séparés.

## Limites

L'échange atomique repose sur Linux ; ailleurs, le repli par deux renommages restaure l'ancien catalogue sur erreur mais laisse un court intervalle sans `catalog/`. La présélection reste lexicale. L'activation par projet n'existe pas encore.
